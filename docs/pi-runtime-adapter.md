# 官方 Pi 运行态适配

插件支持未修改的官方 Pi 1.5.0，不需要替换安装、SDK 补丁、全局 prototype 包装或另一份 Pi 宿主。

## 调度模型

参考 MCode `3c21163c85a9684030cb147bfef48c6284fa3c46` 的子 Agent 调度思路：

- 前台和后台共用持久任务状态机，先保存准入记录，再执行独立子会话。
- 前台等待结果，后台返回任务句柄；终态结果先保存，再通知所属父会话读取。
- 运行中追加进入同一逻辑任务；闲置续接创建新任务 ID，保留子历史及原有权限上界。
- 任务角色、执行状态、Verifier 判定、输出和清理状态分别记录。取消必须落实到实际执行，崩溃后不自动重放。

Pi SDK 提供子会话、模型、工具执行和消息队列；插件的 Engine 只负责调度、所有权、持久化及结果交付，不复制 MCode 的完整宿主。

## 资源与权限

`parent-tools.ts` 使用官方接口取得当前可调用工具及其元数据。它不尝试从工具列表还原扩展工厂或 MCP 服务器配置，也不重扫磁盘。

`before_agent_start` 提供系统提示词的可变选项；到 `agent_start` 时，插件读取最终的 Skills 列表，随后释放对选项的引用。子会话按角色选择及历史上界筛选这些 Skills，不解析提示词中的 XML 来推断授权。

扩展工具和 MCP 工具通过父工具管线执行，纯权限 hook 留在父会话的原始实例中。MCP 沿用父连接，既不复制凭据，也不为子会话再启动连接。Task 声明 `reachesTools: all`，让 Pi 的 MCP hook 在准入前准备所需工具。角色来源和服务器选择只能缩小可用范围。

子会话不重新执行父扩展工厂。因此扩展的 UI、会话启动回调及其他非工具生命周期行为不会复制到子会话；工具本身及其原有权限检查仍在父实例执行。需要获知子会话自身历史的专用扩展，不能假定自己已在子会话中运行。

## 工具桥

每个子调用按以下顺序执行：

1. 子 Pi SDK 验证参数，并检查角色、历史工具上界和当前 codemode 状态。
2. 插件内部使用当前任务控制工具的原生 wrapper 构造工具上下文。私有待派发表只接受插件刚登记的调用，不提供新的模型可见工具，也不走 Task 准入分支。
3. 该上下文调用官方 `executeTool(target, args)`。插件按调用来源绑定子权限范围，父扩展再发起的嵌套调用也须通过同一角色、工具及服务器限制，已结束调用留下的旧上下文不再获准执行。目标工具仍经过父 Pi 的参数验证、`tool_call`、权限处理、实际执行及 `tool_result`。
4. 子会话保存真实结果；原生命令继续使用所属子任务的取消信号和清理证明。

直接调用任意父工具的 `execute` 会绕过父权限 hooks，本插件不这样执行目标工具。内部 wrapper 只用于构造上下文，真实目标只能经 `executeTool` 到达。派发 ID 在父 `agent_end` 后轮换，同一子权限范围内共享有界的原生 nested-call recorder；不会把已结束 Task 的 context 当作后台任务句柄反复使用。

父会话不会回写已返回 Task 结果里的 `nestedCalls`。子工具的完整结果和逻辑调用事实保存在独立子历史中；父终态通知指向持久任务输出，不宣称父 Task 消息包含了完整后台执行日志。

新调用会检查父工具的元数据是否改变；父停用工具时，原生执行管线会拒绝调用。子续接还受已保存工具清单和扩展来源限制，不因父新增工具而自动扩权。聚合 MCP 资源调用受服务器范围限制时，必须显式指定允许的 `server`，不能借未指定服务器的列表调用跨过限制。

## 生命周期

同一父 runtime 内，父 Turn 结束或中止不自动停止已经准入的后台任务。显式 `task_stop` 和 `/tasks stop-all` 会取消所属执行并等待清理。

父会话切换、新建、fork、重载或退出会销毁原始权限上下文。插件在 `session_shutdown` 内取消并排空该 owner 的执行，然后关闭工具桥。后台任务不会跨此边界继续使用旧权限，也不会转交新 owner。历史、结果和回执保留，回到原父会话后可续接。

这是 Pi 的适配选择，不承诺 MCode 宿主的所有会话切换行为相同。独立 SDK backend 仍允许嵌入程序显式提供资源库存及宿主生命周期，但普通插件路径不依赖自定义 SDK 方法。

## 验证

- `parent-tools.test.ts`：四角色真实 Task 入口、纯 hook 的单实例权限、后台完成后的权限拒绝、唯一调用 ID、结果过滤、嵌套角色权限和过期调用上下文、续接、父禁用工具、首次 MCP 准备与连接复用、会话关闭清理。
- `runtime-inheritance.test.ts`、`resource-inheritance.test.ts`：动态和禁用 Skills、扩展选择、文件与运行态 MCP、Shell 设置、受管命令、codemode、模型和冷恢复上界。
- `child-parent-tools.test.ts`：来源、历史工具清单、原始 MCP server 名及聚合资源限制。
- `official-cli-task.test.ts`：未修改的 bundled CLI 从默认插件入口派工，执行允许的写入，验证父 hook 拒绝写入；只用脚本化本地模型，不调用付费服务，检查网络审计和 CLI 文件哈希。
- `scripts/test.mjs`：直接运行官方 SDK 测试，不构建或加载 SDK 补丁覆盖层。

离线测试和本地 stdio MCP 只能证明这些受控路径。真实模型、第三方业务 MCP、其他 Pi 版本及其他平台需要相应验收，不由旧版补丁 SDK 的测试结果替代。
